## 🔴 P0: 策略状态机 (消除人为情绪)

### 问题场景

**场景 1: 信号变了怎么办？**
- 系统昨天输出 `BUY`，痛苦指数 90，仓位 8%。
- 今天痛苦指数降到 85，但价格没变。
- **人**: "卖不卖？减仓还是清仓？" (犹豫)
- **系统**: 明确输出 `REDUCE 50%` 或 `HOLD`

**场景 2: 止损止盈**
- 买入后跌了 5%，但痛苦指数 still 80。
- **人**: "再等等吧，万一反弹呢？" (侥幸)
- **系统**: 严格止损，无条件执行。

### 实现方案

#### 状态机设计

```
状态：Empty (空仓)
  -> 信号 >= 7: OPEN (开仓)
  -> 5 < 信号 < 7: WAIT (观望)
  -> 信号 <= 5: WAIT (等待)

状态：Holding (持仓)
  -> 信号 >= 8.5: ADD (加仓)
  -> 6 < 信号 < 8.5: HOLD (持有)
  -> 4 < 信号 <= 6: REDUCE (减仓)
  -> 信号 <= 4: CLOSE (清仓)
  -> 亏损 >= 5%: CLOSE (止损，最高优先级)
```

#### 实测数据

| 场景 | 输入 | 输出 | 原因 |
|------|------|------|------|
| 空仓 + 强信号 | Strength=9.0 | OPEN | 信号强度 >= 7.0 |
| 持仓 + 信号弱 | Strength=3.5 | REDUCE 50% | 信号减弱 |
| 持仓 + 止损 | Price=13.2 (-5.7%) | CLOSE | 触发止损线 |

## 🟠 P1: 配置热加载 (Hot Reload)

### 问题场景

**场景**: 盘中发现 `stop_loss_pct` 设错了，需要改成 3%。
- **旧流程**: 改配置 -> 重启服务 -> 重新加载数据 -> 错过行情 (5-10 分钟)
- **新流程**: 改配置 -> 自动检测 -> 立即生效 (0 延迟)

### 实现方案

```python
from src.utils.config_hotload import watch_config

def on_change():
    print("配置已更新，策略自动调整!")

watch_config('.env', on_change)
```

**技术细节**:
- 后台线程轮询文件 `mtime`
- 检测到变化自动 `load_dotenv(override=True)`
- 回调通知业务逻辑更新

## 🟠 P1: 看门狗服务 (主动监控)

### 问题场景

**场景**: 半夜 2 点数据爬虫挂了。
- **旧系统**: 第二天早上 9 点才发现，错过上午行情。
- **新系统**: 5 分钟内发现并告警，自动切换备用源。

### 实现方案

```python
from src.services.watchdog import start_watchdog

def telegram_alert(msg):
    send_telegram(msg)

start_watchdog(telegram_alert)
```

**巡检项**:
1. **数据新鲜度**: 特征数据 > 1 小时未更新？告警！
2. **磁盘空间**: 剩余 < 10%？告警！
3. **API 可用性**: (待扩展) 连续失败 3 次？告警！
