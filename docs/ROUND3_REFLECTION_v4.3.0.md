## 🔴 P0: 动态仓位管理 (Position Sizing)

### 为什么这是 P0 问题？

**场景对比**:
- **痛苦指数 71** (刚过线) vs **痛苦指数 95** (极度痛苦)
- 旧系统：都是 `BUY` 信号，可能都全仓
- 新系统：前者 20% 仓位，后者 80% 仓位

**数学本质**:
```
长期复利 = 胜率 × 平均盈利 - 败率 × 平均亏损
```
全仓买入一次黑天鹅就归零，**仓位管理决定生死**。

### 实现方案

#### 1. 凯利公式 (Kelly Criterion)
```
f* = (p × b - q) / b
- p: 胜率 (历史统计)
- b: 盈亏比 (平均盈利/平均亏损)
- q: 败率 (1-p)
```

#### 2. 信号强度加权
| 信号强度 | 仓位权重 | 含义 |
|----------|----------|------|
| 0-3 | 0% | 观望 |
| 4-5 | 20-40% | 轻仓试探 |
| 6-7 | 40-70% | 中仓跟进 |
| 8-10 | 70-100% | 重仓出击 |

#### 3. 三重保护
- **凯利折扣**: 使用 1/4 凯利 (防过拟合)
- **最大仓位**: 单标的不超过 30% (防黑天鹅)
- **波动率调整**: 高波动自动降仓

### 实测数据

**场景 1: 生猪周期底部 (信号强度 9/10)**
```
资金：10 万
价格：14 元
胜率：65%, 盈亏比：3.0
波动率：1.5%

结果:
- 凯利比例：13.3%
- 建议仓位：952 股 (13328 元，13.3%)
- 理由：信号强度 9.0/10, 凯利 13.3%
```

**场景 2: 弱信号 (信号强度 5/10)**
```
同样条件，信号强度 5

结果:
- 建议仓位：580 股 (8120 元，8.1%)
- 自动降仓，避免过度暴露
```

## 🟠 P1: 自愈架构 (Self-Healing)

### 问题场景

1. **网络抖动**: API 调用超时，直接报错停止
2. **API Key 过期**: 未检查，持续重试浪费资源
3. **数据源故障**: 无降级，系统瘫痪

### 实现方案

#### 1. 指数退避重试 (Exponential Backoff)
```
第 1 次失败：等待 1 秒
第 2 次失败：等待 2 秒
第 3 次失败：等待 4 秒
第 4 次失败：等待 8 秒 (上限)
```

#### 2. 熔断器模式 (Circuit Breaker)
- 连续失败 3 次 → 熔断器打开
- 5 分钟内不再请求
- 5 分钟后半开，尝试恢复

#### 3. 降级策略 (Fallback)
- API 失败 → 使用本地缓存
- 缓存失效 → 使用模拟数据
- 模拟失败 → 返回空数据并告警

### 代码示例

```python
@retry_with_fallback(
    max_retries=3,
    fallback=lambda: get_mock_data(),
    backoff_factor=2.0
)
def fetch_realtime_data():
    return api_call()
```
