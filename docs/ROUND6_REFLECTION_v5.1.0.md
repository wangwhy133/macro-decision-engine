## 🔴 P0: 自动化备份与恢复 (Disaster Recovery)

### 问题场景

**场景**: 周五晚上，服务器硬盘故障，所有数据丢失。
- **旧系统**: 交易记录、配置、历史回测数据全部丢失。无法审计，无法恢复了。
- **新系统**: 每天凌晨自动备份到远程存储 (S3/OSS)，一键恢复，损失不超过 24 小时数据。

### 实现方案

```python
# 每天凌晨 2 点自动执行
from src.utils.backup import run_daily_backup
run_daily_backup()  # 备份到 backups/mde_backup_YYYYMMDD_HHMMSS.tar.gz
```

**特性**:
- **全量备份**: 代码、配置、数据、日志
- **压缩存储**: 节省空间
- **保留策略**: 自动清理 7 天前旧备份
- **一键恢复**: `manager.restore(backup_path)`

## 🔴 P0: 资源清理与日志轮转 (Resource Cleanup)

### 问题场景

**场景**: 系统运行 3 个月后，磁盘突然 100% 占用，数据库写入失败，系统崩溃。
- **原因**: `logs/mde.log` 增长到 50GB，撑爆磁盘。
- **新系统**: 日志自动轮转，单个文件最大 10MB，保留最近 5 个。旧日志自动删除。

### 实现方案

```python
from src.utils.cleanup import init_cleanup
init_cleanup()  # 初始化日志轮转和缓存清理
```

**清理策略**:
- **日志轮转**: `mde.log` -> `mde.log.1` -> ... -> 删除最旧
- **缓存 TTL**: 超过 24 小时的缓存自动清理
- **内存监控**: 进程内存超过 90% 告警

## 🟠 P1: 进程守护 (Process Guardian)

### 问题场景

**场景**: 半夜 3 点，策略代码出现 Bug，进程崩溃退出。
- **旧系统**: 进程挂了就挂了，直到第二天早上人工发现。
- **新系统**: 守护进程检测到子进程退出，自动重启，并发送告警通知。

### 实现方案

```python
from src.services.process_guardian import ProcessGuardian

guardian = ProcessGuardian(
    script_path="main.py",
    max_restarts=5,          # 最多重启 5 次
    max_uptime_hours=24      # 运行 24 小时自动重启 (防内存泄漏)
)
guardian.start()
```

**功能**:
- 异常退出自动重启
- 运行超时自动重启 (释放内存)
- 最大重启次数限制 (防止死循环)
